## 每日签到推送改到 9:00 + 结果图片卡片 + 新人登录发图

用户需求（三件事）：
1. 每日签到结果推送时间从 0:30 改到早上 9:00
2. 每日签到结果推送返回一张**和 /skd 指令一样**的结果图片
3. 每当有**新的人** login 成功后也发一张 sdk 指令的结果图片

### 签到时间 0:30 → 9:00

改了三处默认值（schema / `_init_config` / `_get_config`）+
`_start_auto_sign_job` 默认参数。

**关键坑：AstrBot 的插件配置是「首次写入后不再回填默认值」的。**
老实例的 `data/config/astrbot_plugin_skland_config.json` 里已经存着
`auto_sign_hour=0` / `auto_sign_minute=30`，只改 `_conf_schema.json` 的
default 完全不生效 —— 那个 default 只在 key 缺失时才被使用。

解法：新增 `_migrate_sign_time()`，在 `initialize()` 里调用。
**只在检测到恰好是旧默认值（0:30）时才改写**，用户自己设过的时间不动。
`save_config` 用 `getattr` 防御性调用（配置对象可能没有该方法），
整体包 try/except 防止迁移失败影响启动。

### 图片卡片

新增配置 `push_card_image`（默认 true），控制两处：
- 每日签到推送 → 私聊推图片卡片
- 新人首次 login 成功 → 附送图片卡片

`/skd` 指令本身的图片开关仍是 `card_image_enabled`（未动）。

**卡片数据必须与 /skd 同源**，否则推送的图和群里看到的会不一致。
做法：把行构建逻辑抽成 `_build_user_row(user_data, today, failed)`，
`/skd` 群聊、`_build_user_rows`、`_private_card_rows` 全部复用它。
`_build_user_rows` 就是把 `_build_user_row` 循环一遍。

推送图片走 `MessageChain().file_image(path)`（AstrBot 的 MessageChain
有 `file_image` 方法；`event.image_result()` 只能用于被动回复）。
`_push_to_user` 加了 `image_path` 参数：有图时只发图不发文本。

「新的人」的判定 = **本次登录前该用户没有任何绑定账号**
（`had_account_before = bool(self._get_accounts(users.get(user_id) or {}))`）。
不是「新增了一个 token 账号」—— 给老账号补签到状态不该重复发图。

## 修正：签到与推送拆成两个独立时间（v1.6.0 → v1.7.0）

用户澄清上一版做错了：**不是「9:00 既签到又推送」，而是 8:30 签到、9:00 推送，
两个时间点不要放一起。**

### 拆成两个独立定时任务

| job id | 函数 | 默认时刻 | 职责 |
|--------|------|---------|------|
| `skland_auto_sign` | `_auto_sign_all_users` | 8:30 | 只请求接口 + 落库，**不发任何消息** |
| `skland_auto_push` | `_push_daily_results`（新） | 9:00 | 读当天落库结果 → 推卡片 + 群播报 |

拆开后的实际收益（不只是「配置好看」）：
- 签到阶段的随机延时（`auto_sign_delay`）+ 接口重试不会推迟推送，**推送时刻是死的**
- 8:30→9:00 的半小时正好用来消化延时与重试
- 插件在 9:00 重启也能推 —— 结果早在 8:30 就落库了

### 推送阶段如何判断「今天的结果」

不新增临时字段，直接读已有的 `account["last_result"]["time"]`
（ISO 串），取前 10 位比对日期：

```python
todays = [a for a in accounts
          if str((a.get("last_result") or {}).get("time") or "")[:10] == today]
```

这样推送是**纯读操作**：不重复请求森空岛，也不依赖内存里的临时状态，
重启后照样能推。曾考虑过在签到阶段写 `last_auto_sign_bodies` 等字段，
但那会让推送依赖签到阶段的写入，纯读last_result 更干净。

失败结果单独分流：正文以「签到失败」开头的归入 failures 段，
用 `startswith` 判定而不是新增 `failed` 字段。

### 配置新增 3 项

`push_hour`(9) / `push_minute`(0) / `push_enabled`(true)，
schema / `_init_config` / `_get_config` 三处同步。
`push_enabled=False` 时 `initialize` 根本不注册推送任务（而不是注册后再跳过）。

### 迁移加了一次性标记位

上一版只判`hour==0 and minute==30`，这次历史默认值有两个（0:30 和 1.6.0 的 9:00），
都要迁到 8:30。加了 `_sign_split_migrated` 标记位：

- 命中历史默认值 → 改成 8:30，补齐 push_* 三项，写标记，落盘
- 标记已存在 → 直接 return

**为什么必须一次性**：如果只按值判断，用户日后手动把签到调回 9:00，
每次启动都会被改回 8:30，永远改不动。标记位让迁移只跑一次。
注意标记位本身也要落盘，所以即使时间没变也会 `save_config` 一次。
