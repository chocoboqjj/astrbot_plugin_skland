# AstrBot Plugin - 森空岛签到

[![Build and Release](https://github.com/chocoboqjj/astrbot_plugin_skland/actions/workflows/release.yml/badge.svg)](https://github.com/chocoboqjj/astrbot_plugin_skland/actions/workflows/release.yml)

森空岛自动签到插件，支持明日方舟和终末地签到，**同时适配 OneBot(NapCat/LLOneBot) 与 QQ 官方机器人**。

> 本仓库基于 [Azincc/astrbot_plugin_skland](https://github.com/Azincc/astrbot_plugin_skland) 修改，
> 原作者为 [Azincc](https://github.com/Azincc)，遵循 MIT 许可。主要改动见「从 v1.4.0 升级」。

## 功能

- **skd** (群聊):        查看所有已绑定用户的签到状态（各群名单一致）
- **skd** (私聊):        查看自己的签到状态（读取最近一次自动签到结果）
- **skdlogin** (全部):   使用 token 登录并立即签到（群聊中会自动撤回 token 消息）
- **skdlogout** (全部):  登出并移除 token（带 token 参数时只移除该账号）
- **skdusers** (全部):   查询用户统计，普通用户仅显示签到人数和名额
- **skdhelp** (全部):    查看帮助
- **skdcheck** (全部):   诊断签到卡片图片是否可用（缺依赖时会给出安装指引）
- **skdmerge** (管理员): 检测并合并重复账号记录

> **签到名单取自「所有已绑定用户」**，与群无关 —— 各群看到的名单始终一致，
> 新登录的用户无需主动发 `/skd` 也会出现在名单里。

### 多账号支持

同一个人可以绑定**多个森空岛账号**（多次 `/skdlogin` 即可，同一 token 视为更新）：

```
📋 森空岛签到
  明日方舟/终末地 ✓/◐    刀客/刀客2｜终末A/终末B
  明日方舟        ✓      小明
```

- 同一游戏的多个角色用 `/` 分隔
- 两个游戏之间用 `｜` 分隔，避免混淆
- 状态标记：**✓** 全部已签 / **◐** 部分已签 / **✗** 未签
- `/skdlogout <token>` 可单独移除某个账号；不带参数则解除当前平台绑定
- 签到奖励另起一行显示，两个游戏的奖励用 `｜` 分隔
- 名字过长时会**自动缩小字号**以完整显示，实在放不下才截断并加省略号

### 重复账号

**一个森空岛账号（token）只允许绑定一次**，重复登录只更新状态，不会新增记录。

可能导致重复的两个原因及处理：

| 原因 | 处理 |
|------|------|
| 复制 token 时混入隐形字符（零宽空格、全角空格、BOM、方向标记等 18 种） | 登录时**自动规范化 token**，去掉所有不可见字符与空白 |
| 同一个人从不同平台（OneBot 的 QQ 号 / QQ 官方的 openid）分别登录 | 自动**复用**已有记录，并为其建立别名，两者指向同一份数据 |

- 登录时若该 token 已绑定，回复中会明确提示「已复用原记录」或「本次为更新签到状态」
- **手动清理**：对历史遗留的重复数据，管理员可发送 `/skdmerge` 一次性合并。
  它会**按规范化后的 token** 归组，因此因隐形字符造成的重复也能检出，
  同时顺手把脏 token 写回干净形式

```
🔍 发现 1 组重复账号：
═══════════════
  • 甲（token N6QKb2***）
    → 已合并为 1 条记录
═══════════════
✅ 已合并 1 条重复记录，当前 1 个用户
```

## 使用

### 获取 Token

1. 登录 [森空岛](https://www.skland.com/)
2. 访问 [森空岛/account/info/hg](https://web-api.skland.com/account/info/hg)
3. 找到返回的 JSON 中的 `{"content":"XXX"}`
4. 复制 `XXX` 部分

### 登录与签到

1. 发送 `/skdlogin XXX` 进行登录
2. 登录成功后会自动执行一次签到
3. 之后可以发送 `/skd` 查看签到状态

> ⚠️ **token 等同账号密码**。私聊提交最安全；
> QQ 官方机器人若无法私聊，可在群里发送，插件会**立即调用官方接口撤回**该条消息
> （需机器人在群里是管理员且发送未超过 2 分钟，失败时会提示你手动删除）。

## 指令写法

| 场景 | 写法 |
|------|------|
| 私聊 | `/skdlogin <token>`、`/skd`、`/skdlogout`、`/skdusers` |
| 群聊 | `/skd` |

> **注意**：AstrBot 的指令默认需要 `/` 前缀。插件额外做了兜底，`skd`、`签到` 等不带斜杠的写法也能识别。

## 平台适配说明（重要）

QQ 官方机器人与 OneBot 的能力差异较大，本插件会**自动识别平台并采用对应策略**，无需手动配置。

| 能力 | OneBot / NapCat | QQ 官方机器人 |
|------|-----------------|----------------|
| 定时私聊推送 | 支持 | **不支持**（官方已取消主动推送） |
| 群内主动播报 | 支持 | 需群主开启「允许主动发言」 |
| 用户 ID | QQ 号 | openid（与 QQ 号不通用） |
| 群聊 token 撤回 | 不适用 | 支持（需机器人为群管理员） |

### 签到结果如何送达

- **OneBot**：定时任务签到完成后，照旧私发结果给你。
- **QQ 官方**：定时任务**照常执行签到**，但结果只写入数据库；你发送 `/skd` 时读取并展示，并附带签到时间。

### QQ 官方机器人无法私聊时

官方机器人的单聊（C2C）需要**用户主动发起**，且机器人不能主动发起私聊。
若你的机器人收不到私聊消息，可改在群里发送 `/skdlogin <token>`：

- 插件会**立即调用官方接口撤回**你发出的那条消息，群里只留下提示
- 撤回走的是官方接口
  [`DELETE /v2/groups/{group_openid}/messages/{message_id}`](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages_message_id.delete.html)

**只要消息里带了 token，无论结果如何都会撤回** —— 包括登录成功、
接口异常、达到用户数上限、token 已被他人绑定等所有退出路径。
每条回复末尾都会附上撤回结果。

**撤回的官方前提条件**（不满足则撤回失败）：

| 条件 | 不满足时的错误码 | 插件提示 |
|------|-----------------|---------|
| 机器人须为该群**管理员** | `40062003` 无操作权限 | 机器人不是群管理员，无权撤回他人消息。请群主在群聊设置里把机器人添加为管理员 |
| 消息发送未超过 **2 分钟** | `40064004` 超出撤回时限 | 消息发送已超过 2 分钟，官方接口不允许撤回 |
| 请求参数有效 | `40061001` 参数无效 | 请求参数无效 |
| 服务端正常 | `50065001` 撤回失败 | 撤回失败，请稍后重试 |

#### ⚠️ 遇到 `40062003 无操作权限` 时

这是线上最常见的情况，**唯一的解法是把机器人设为该群管理员**：

> 群聊设置 → 管理 → 群机器人/管理员 → 添加你的机器人

官方规则：机器人是普通成员时，只能撤回**机器人自己**发的消息，撤不掉用户发的那条。
这个限制绕不过去，插件无法通过代码规避。

设为管理员后无需重启，下次登录即可正常撤回。插件对同一群体的此类失败只详细记一次日志，避免刷屏。

**在解决之前**，建议引导用户改用私聊发送 `/skdlogin` —— 私聊内容不会留在群里。

> 💡 想恢复私聊能力：在 QQ 开放平台「开发设置 → 事件订阅」勾选 **C2C 消息**，
> 并在 AstrBot 机器人配置里开启「启用消息列表单聊」。

这是因为腾讯已于 2025-04-21 取消 QQ 机器人的主动消息推送能力，官方仅保留「响应式交互」——必须用户先发起对话，机器人才能回复。因此 QQ 官方平台无法做到「每天主动私发签到结果」。

### QQ 官方平台使用须知

1. 若要接收全量群消息，需在手机端群设置里把「机器人可获取的群聊消息范围」设为「获取群内全部消息」。
2. 机器人**只能被添加到自己是群主的群聊**。
3. 正式环境需要配置 IP 白名单；沙箱环境最多 20 人。

## 配置项

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `auto_sign_enabled` | `true` | 自动签到总开关 |
| `auto_sign_hour` | `0` | 自动签到执行小时（0-23） |
| `auto_sign_minute` | `30` | 自动签到执行分钟（0-59），默认 0:30 执行 |
| `auto_sign_delay` | `10` | 每个用户之间的随机延时上限（秒），规避风控 |
| `max_users` | `10` | 最大绑定用户数，0 表示无限制 |
| `show_player_name` | `true` | 显示森空岛昵称还是平台昵称 |
| `push_mode` | `auto` | `auto` 按平台自动判断 / `private` 强制私聊推送 / `pull` 强制仅落库 |
| `group_broadcast_enabled` | `false` | 自动签到后向群播报汇总，失败自动静默降级 |
| `live_query_in_group` | `false` | 群聊 `/skd` 是否实时请求森空岛 |
| `card_image_enabled` | `false` | `/skd` 以图片卡片输出签到状态 |
| `card_theme` | `dark` | `dark` 深色 / `light` 浅色卡片 |
| `token_conflict` | `smart` | 已绑定的 token 被再次绑定时如何处理 |

### token 冲突处理

**只支持 QQ 官方平台**，sender_id 即稳定的 openid，因此「token 已绑在别的用户下」
即可断定是他人冒用/共享，**默认一律拒绝**。

| 配置 | 行为 |
|------|------|
| `reject`（默认） | 一律拒绝，并提示当前绑定者与处理途径 |
| `merge` | 自动复用原记录，仅用于管理员清理历史重复数据 |

被拒绝时：

```
❌ 绑定失败：该森空岛账号已被其他用户绑定

• 当前绑定者：玩家甲
• 如果这是你自己的账号，请用当前 QQ 重新登录，
  或联系管理员使用 /skdmerge 合并记录
• 如果是账号共享，请让各自使用自己的 token
```

> 历史遗留的重复数据用 `/skdmerge` 一次性清理（仅管理员）。

> 群聊 `/skd` 默认**读取数据库**中的最近一次签到结果，不产生额外请求。

### 签到请求时机

**今日已签到的账号不会被重复请求。** 签到状态以日期形式落库（`last_sign`），
跨天自然失效 —— 等价于**每日 0 点自动重置**，无需额外的重置任务。

```
00:00  签到状态重置（日期变化，last_sign 失效）
00:30  定时任务执行，对今日未签到的账号发起签到
```

- 群聊 `/skd`（开启 `live_query_in_group` 时）：只请求**今日未签到**的账号，
  已签到的直接读落库结果
- 定时自动签到：同样跳过今日已签到的账号
- 定时任务默认在 **0:30** 执行，避开整点的接口高峰

> 单个账号请求失败不会影响该用户的其他账号；只有全部账号都失败且没有任何
> 有效签到结果时，才会显示「查询失败」。

### 签到卡片图片

开启 `card_image_enabled` 后，`/skd` 只会输出一张签到状态卡片图片（不再附带纯文本）。图片渲染失败时自动回退为纯文本。

渲染只需要 **Pillow**（已在 `requirements.txt` 中列出，AstrBot 会自动安装）—— 字体已随插件打包，**无需在系统安装中文字体**，各平台渲染效果一致。

字体查找优先级：

1. 插件内置字体（`fonts/` 目录）—— 跨平台效果一致
2. 用户本机安装的中文字体（`~/Library/Fonts`、`~/.fonts` 等）
3. 系统级中文字体（`Hiragino Sans GB`、`NotoSansCJK`、`wqy-zenhei` 等）

> ⚠️ **字体许可提示**
>
> 内置的筑紫A丸（BC筑紫S丸SC Bold）是 **Fontworks 的商业字体**，
> 并非 OFL 等自由许可。随插件对外分发可能违反其授权条款。
>
> 若要公开发布到插件市场，建议把 `fonts/` 里的字体换成
> Noto Sans SC / Sarasa Gothic SC 等开源字体，或直接删除 `fonts/` 目录
> （插件会自动回退到查找系统字体）。详见 `fonts/README.md`。

> 💡 发送 `/skdcheck` 可查看当前使用的字体与渲染自检结果。

> **字体缺失或 Pillow 未安装时，插件会自动回退为纯文本输出**，不会报错也不会影响签到功能。

### 图片没出来？先跑 /skdcheck

如果 `/skd` 返回的还是文字而不是图片，发送 `/skdcheck` 诊断：

```
🔍 签到卡片诊断
═══════════════
图片开关: ✅ 已开启
卡片主题: dark
Pillow: ✅ 已安装 12.3.0
中文字体: ✅ /System/Library/Fonts/Hiragino Sans GB.ttc
渲染测试: ✅ 成功（/tmp/skland_card_xxx.png）
```

它会逐项列出问题并给出对应的安装命令。常见情况：

| 诊断输出 | 处理方式 |
|---------|---------|
| 图片开关 ❌ 未开启 | WebUI →「插件配置」→ 勾选「签到卡片图片」 |
| Pillow ❌ 未安装 | `pip install Pillow`（AstrBot 通常会自动装） |
| 中文字体 ❌ 未找到 | 见上方 Docker 部署说明 |
| 渲染测试 ❌ 失败 | 查看 AstrBot 日志中的 `卡片渲染失败` 报错 |

### 接口日志

所有森空岛接口的请求参数与原始返回都会打在 AstrBot 日志里（`[森空岛]` 前缀），便于排查接口变更或签到失败：

```
[森空岛] -> POST https://as.hypergryph.com/user/oauth2/v2/grant
  请求体: {"appCode": "4ca99fa6b56cc2ba", "token": "ABCD***MNOP", "type": 0}
[森空岛] POST https://as.hypergryph.com/user/oauth2/v2/grant -> 200 (第 1 次尝试)
{"status": 0, "data": {"code": "AUTH***3456"}}
```

**敏感字段会自动脱敏**（保留首尾各 4 位）：用户 token、cred、sign、dId、deviceId、授权码等。接口状态码与业务数据（如奖励列表）完整保留，不会被误遮。

> 响应超过 2000 字符会截断，避免刷屏。

## 从 v1.4.0 升级

- 群记录结构会自动迁移为带平台前缀的格式，无需手动处理
- 原有 token 绑定数据保留，新增 `umo_by_platform` 字段用于多平台共存
- 同一个用户在 OneBot 与 QQ 官方平台各绑定一次后，**任一平台登出不会影响另一平台**
- 新增裸指令兜底：`skd`、`签到` 等无需 `/` 前缀的写法也能识别
- 新增 `game_names` 字段，按游戏分别保存昵称。一个森空岛账号可同时绑定明日方舟和终末地，两者的角色名往往不同，现在会各用各的名字显示（旧数据会在下次签到后自动补齐）
- 新增 `game_awards` 字段，按游戏分别保存奖励（旧数据会自动回退为从文本解析；奖励道具名现已不在列表中展示）
- 新增 `accounts` 字段，**支持同一个人绑定多个森空岛账号**。旧数据只有单个 token，会在下次登录时自动迁移为 `accounts` 结构，无需手动处理
- `/skdlogout` 支持带 token 参数，只移除指定的账号
